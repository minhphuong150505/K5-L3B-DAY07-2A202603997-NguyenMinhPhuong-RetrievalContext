Tỷ lệ đạt theo nhóm (ADVANCED.md: đúng + đủ + citation hỗ trợ; từ chối đúng)

Chưa chấm test.

A0 = Day 6 nguyên trạng (dense, index B, top-3). A1 = + index V + hybrid RRF, top-5. A2 = A1 + rerank + read_page + kiểm trích dẫn nguyên văn & luật năm/đối tượng. A3 = A2 nhưng kiểm trích dẫn có dung sai (số phải khớp, ≥60% từ, sửa ID). A4 = A3 + luật trình bày số (định dạng VN, điểm phần trăm, kiểm đối tượng/chỉ tiêu theo tiêu đề chunk). Tiêu chí chọn công bố trước khi chạy test (results/selection.json): (1) số câu dev đạt, (2) từ chối đúng, (3) ít từ chối nhầm, (4) chi phí/thời gian.

8. Kịch bản demo (≈ 7 phút)

  1. 0:00 Vấn đề. Mở mục Tổng quan: tài liệu 100 trang, nhiều số liệu nằm trong biểu đồ; RAG chỉ đọc text sẽ trả lời sai hoặc bịa.
  2. 0:45 Kiến trúc. Chỉ sơ đồ: dùng lại pgvector + embedding Day 6 (index B), thêm index V đọc bảng/biểu đồ bằng vision; 4 retriever; agent có tool và tự quyết số lượt tìm.
  3. 1:45 Benchmark minh bạch. Mở benchmark/questions.json, chỉ một câu biểu đồ: trang, vùng, evidence. Nhấn mạnh chia dev/test trước, test không dùng để chỉnh.
  4. 2:30 Live demo câu có bằng chứng. Mở http://127.0.0.1:8765/ (server python -m src.rag.demo_server --warm), chọn câu t17 (multi-hop tr. 40 + tr. 37), bấm ▶ Chạy agent: pipeline sáng theo từng bước, bảng kết quả mỗi lần tìm, câu trả lời có phép tính và citation bấm được.
  5. 3:30 Chứng minh trong DB. Bấm citation → khung Chunk inspector hiện đúng dòng trong pgvector, câu SQL và ảnh trang PDF; hoặc chạy python -m src.rag.verify --trace results/agent/test/A3/traces.json --id t17 --find "20,5" → in đúng dòng trong bảng chunks (index, trang, hash) và đối chiếu PDF; mở ảnh trang gốc.
  6. 4:30 Câu thiếu bằng chứng + so sánh retriever. Chạy câu t25 (doanh thu B2C 2024) → agent tìm nhiều lần rồi từ chối; so với baseline A0 từng bịa số năm khác trên dev (d17). Bấm “So sánh 4 retriever” để thấy dense/BM25/hybrid/rerank xếp hạng khác nhau thế nào.
  7. 5:15 Một lỗi thật. Mở thẻ “Một lỗi” ở mục 7: chỉ ra nguyên nhân (đọc biểu đồ tròn / chọn sai năm) và giới hạn.
  8. 6:00 Số liệu & đánh đổi. Bảng mục 4–5: chất lượng tăng từ A0 → A2, đổi lại nhiều lượt gọi hơn, rerank chậm trên CPU; tổng chi phí API $0.46.
  9. 6:40 Kết luận + Q&A. Giới hạn ở mục cuối; mọi số liệu sinh tự động từ results/.

Chuẩn bị trước: docker --context default compose -p day6_student_starter up -d (thư mục starter Day 6), kiểm tra .env, chạy thử một câu để nạp model (lần đầu ~25 s). Nếu mạng/API lỗi: tab “Phát lại trace đã lưu” (hoặc mở http://127.0.0.1:8765/?replay=test/A3/t17&gold=1) phát lại đúng trace thật đã ghi, không gọi API, không bịa kết quả.

9. Cách kiểm chứng một câu trả lời

  1. Lấy chunk_id trong citation, ví dụ sach-trang-tmdt-2023:p40:V2 (trang 40, index V, khối 2).
  2. Truy vấn trực tiếp DB: SELECT strategy, page, text, metadata FROM chunks WHERE chunk_id = '…';
  3. Mở PDF gốc đúng trang (hoặc work/pages_hd/p040.png), so từng số, đơn vị, năm.
  4. Hoặc chạy python -m src.rag.verify --chunk … --find "…": in dòng DB, kiểm chuỗi trong text layer PDF, hash PDF và nguồn tải.
